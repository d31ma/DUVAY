Sync status

w-sync-status tells the user whether the app is online and how fresh the copy of the data on this device is, for example “Offline · updated 08:12 · 3 waiting to send”. It is one of the offline states pieces (docs/offline-states.md). Set state to online, syncing, offline, locked, sending or sent, and give it updated-at, pending, attention and sent. Every state shows an icon and words, never colour alone.

States

When the state is online and nothing waits, the bar is hidden. Add show-online to keep it visible with “Up to date”.

Catching up

While syncing, syncing-updated-text replaces the time text, for example “Getting changes since 08:12”. progress (0 to 1) draws a 2 px line along the bottom of the bar while syncing or sending. The line is hidden from screen readers, and it does not move with reduced motion.

Sending the queue

While the app sends what was written offline, set state="sending", sent to the items sent so far and pending to the items still waiting (the one being sent counts as waiting). The bar shows “Sending… · 3 of 4” in place of the waiting count. queue-text changes the words; it takes {current} and {total}.

Sending… · 3 of 4

All sent

When the queue is empty, set state="sent" with the count in sent. The bar shows “Up to date · 4 sent”, screen readers hear “Up to date. 4 sent.” once, and the bar hides itself after sent-timeout milliseconds (4000; 0 keeps it). With show-online it then shows “Up to date”. Start the next round with another state. The demo keeps the summary with sent-timeout="0".

Items that need the user

attention counts the items the server refused. Put the app’s own button in the actions slot; the element has no events. In the sent state the bar also counts the others, “3 others sent” (others-sent-text), and it does not hide while attention is above 0. An empty online-text leaves the state words out, so the attention text leads.

A “Details” button

The bar itself is never a button and has no link mode, so it never takes focus. To open a sync panel or a settings page from the bar, put a Details button in actions, and give it aria-haspopup="dialog" when it opens a dialog. On a phone one button stays on the line of the text and the text wraps beside it; wider actions move under the text.

Details

Translated text

Every text has an attribute. {time} and {count} are filled in. Times and numbers follow the closest lang (on the element or a parent), then the page’s lang. hour-cycle="h23" or "h12" chooses 24 or 12 hours; without it the language decides (en shows “08:12 AM”, en-GB “08:12”).

Every text with a count has plural forms: add -zero, -one, -two, -few, -many or -other to its name, for example pending-text-one and pending-text-other. The form is chosen with Intl.PluralRules for the element’s language. A missing form falls back to -other, then to the plain text, then to the English default. The count texts are pending-text, attention-text, queue-text (by {total}), sent-text, others-sent-text and sent-announce-text.

Accessibility

  • The visible text is not a live region, so changes to the time and the counts are never announced.
  • The element owns one hidden role="status" line. It speaks, politely, only when state changes: the offline text, the locked text, “Back online” when the state leaves offline or locked, and “Up to date. 4 sent.” once when it turns sent. syncing and sending are not announced, and neither is the end of the sent summary.
  • What is heard can differ from what is seen: offline-announce-text and locked-announce-text take {time}, for example offline-announce-text="Offline. Showing the copy on this device, updated {time}.". Without updated-at, a text with {time} falls back to the state words. sent-announce-text takes {count} and plural forms; back-online-text is already only heard.
  • Changes within 2 seconds make one announcement, or none if the state ends where it started. Nothing is announced on first display.
  • The element never takes focus. Buttons in actions keep their normal tab order.
  • With reduced motion, a still icon replaces the spinner and the progress line jumps instead of moving. The layout mirrors for right-to-left languages.
  • Use one w-sync-status per page for a state: two elements would announce the same change twice.
