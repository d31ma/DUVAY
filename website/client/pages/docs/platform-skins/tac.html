Platform skins

DuVay ships a skin for each of the five platforms it targets. A skin is selected with the w-os attribute on <html>, which is orthogonal to w-theme: every skin works in light, dark, auto, and high-contrast.

Write the operating-system name. Each platform vendor also has a name for its design language, and those are accepted as aliases — every skin rule matches both, so the two are interchangeable:

PlatformWriteAlso acceptedDesign language
Web (no skin) w-os="" — DuVay's own
iOS w-os="ios" — Apple HIG
Android w-os="android" w-os="material" Material 3
macOS w-os="macos" — Apple HIG
Windows w-os="windows" w-os="fluent" Fluent 2
Linux w-os="linux" w-os="adwaita" libadwaita / GNOME

Install one skin

Applications import a single skin, not all five. Each entrypoint is the full framework plus one platform layer.

<link rel="stylesheet" href="https://d31ma.github.io/DUVAY/latest/duvay-android.min.css">
  <script src="https://d31ma.github.io/DUVAY/latest/duvay.min.js" defer></script>

Or layer a skin onto an existing duvay.css:

@import "https://d31ma.github.io/DUVAY/latest/duvay.css";
  @import "https://d31ma.github.io/DUVAY/latest/platforms/macos.css";

Detection

duvay.js sets w-os from the user agent when the attribute is absent. An explicit attribute always wins, so you can pin a skin or opt out entirely:

<!-- pin the Android skin everywhere -->
  <html w-os="android">

  <!-- opt out of skinning; base DuVay only -->
  <html w-os="">

What a skin changes

A skin may override platform tokens: font family, motion duration and easing, the elevation model, chrome heights, switch geometry, focus rings and scrollbars. It may also restructure individual components where platforms genuinely diverge — sheet corners, dialog action alignment, filled field shape.

A skin may not override brand tokens: colour, control size, the radius scale, or the type scale. Those are what keep an app recognisably the same product on every platform, and bun run tokens:check fails a skin that touches them.

This is a deliberate correction. The first version of these skins varied control height from 22 px on macOS to 48 px on Android — a 2.2× spread that read as five different design systems rather than one product with a native accent. Density is still available per app through DuVay's own size variants; it is just no longer decided by the operating system.

Keeping colour out of skins also means the WCAG AA guarantees verified by tokens:check hold for every skin × theme combination without re-validation.

Density

Control size is not something a skin decides — but it is something an application can. The w-density attribute rescales control geometry, orthogonal to both w-theme and w-os:

<html w-density="compact">   <!-- 32px controls, pointer-first -->
  <html w-density="comfortable">  <!-- 40px controls, the default -->

It can also scope to a subtree, so a dense data table can sit inside a comfortable page:

<section w-density="compact">
    <table class="w-table">…</table>
  </section>

duvay.js sets w-density="compact" automatically alongside w-os="macos", because macOS controls genuinely are denser than the touch platforms'. As always, an explicit attribute wins — set w-density="comfortable" on <html> to opt out.

Compact drops --w-touch-min to 28 px, below the 44 px touch floor. That is deliberate — compact is for pointer input — and it still clears the 24 px WCAG 2.5.8 AA target-size minimum, which bun run tokens:check enforces for every density. Do not use compact on a touch-first surface.

The per-component modifiers (.w-btn--density-compact and friends) still work and compose with this: the attribute sets the floor, the class overrides one control.

Liquid Glass

The iOS and macOS skins ship translucency and vibrancy via backdrop-filter, gated behind @supports with an opaque fallback. They do not attempt Apple's Liquid Glass: the real implementation is a private CSS property, and the SVG-displacement recreations work in Chromium while falling back to plain blur in Safari and WKWebView — failing on the exact engine they imitate. True Liquid Glass is delivered by the SwiftUI implementation using the system materials API.

Browser floor

Anything past the WebKitGTK 4.1 baseline is gated behind @supports, testing both backdrop-filter and -webkit-backdrop-filter. The Linux skin avoids backdrop-filter entirely — GNOME chrome is flat anyway, so nothing is lost.
