Upgrade guide

DuVay uses CalVer (YY.WW.DD) versioning. Releases are frequent and small; upgrading is usually a one-line change.

Upgrading a CDN install

If you load DuVay from the latest URLs you always get the newest release automatically and there is nothing to do. If you pin to a version, bump the version segment:

<!-- before -->
<link rel="stylesheet" href="https://d31ma.github.io/DUVAY/versions/26.24.12/duvay.min.css">

<!-- after -->
<link rel="stylesheet" href="https://d31ma.github.io/DUVAY/versions/26.27.04/duvay.min.css">

Upgrading a downloaded copy

If you vendored the files from the Download page, replace them with the newest build from the latest URLs (or a pinned version URL) and redeploy.

Before you upgrade

  • Read the release notes for the versions between your pin and the target. Breaking changes are always listed under a Breaking heading.
  • Pinned version URLs never change, so you can upgrade one environment at a time and roll back by restoring the previous pin.

Recent breaking changes

26.31.01 - scoped package name

The npm package moved from duvay-css to @d31ma/duvay-css. Update the dependency and every package import. Hosted GitHub Pages URLs did not change.

# before
npm uninstall duvay-css

# after
npm install @d31ma/duvay-css
/* before */
@import "duvay-css/core.css";

/* after */
@import "@d31ma/duvay-css/core.css";

26.27.04 - attribute prefix rename

Every DuVay-owned data-w-* attribute was renamed to the consistent w-* prefix. Applications using CSS-class components must rename their hooks:

<!-- before -->
<html data-w-theme="dark">
<button data-w-dialog-open="settings">Open</button>

<!-- after -->
<html w-theme="dark">
<button w-dialog-open="settings">Open</button>

A project-wide search for data-w- finds every affected attribute; the replacement is mechanical.
