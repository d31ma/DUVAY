Unit testing

DuVay components render into the Light DOM with plain DuVay class names, so they can be tested with any DOM testing setup. There is no Shadow DOM to pierce and no framework-specific test utilities to install.

Test environment

Any runner with a DOM implementation works: bun test or Vitest with happy-dom or jsdom. Register the components once by importing your vendored copy of the module (see Download).

import "./vendor/duvay/duvay-wc.js";

Waiting for the first render

Components render one microtask after they are connected. After inserting markup, flush the microtask queue before asserting on the generated DOM.

import { test, expect } from "bun:test";

  test("w-btn renders a native button", async () => {
    document.body.innerHTML = '<w-btn variant="filled">Save</w-btn>';
    await Promise.resolve(); // flush the render microtask

    const btn = document.querySelector("w-btn button");
    expect(btn.className).toContain("w-btn-filled");
    expect(btn.textContent).toContain("Save");
  });

Asserting on state and attributes

Configuration is attribute-driven, so state changes are ordinary attribute assertions. Boolean attributes follow native HTML semantics.

test("disabled reflects to the inner button", async () => {
    document.body.innerHTML = '<w-btn disabled>Save</w-btn>';
    await Promise.resolve();

    expect(document.querySelector("w-btn button").disabled).toBe(true);
  });

Events

Components emit native event names (input, change, toggle, close) as bubbling CustomEvents with a detail payload. Listen on the host element like any other DOM node.

test("w-switch emits change with its state", async () => {
    document.body.innerHTML = '<w-switch label="Notify"></w-switch>';
    await Promise.resolve();

    const host = document.querySelector("w-switch");
    let detail;
    host.addEventListener("change", (e) => { detail = e.detail; });
    host.querySelector("input").click();

    expect(detail.checked).toBe(true);
  });

Testing the CSS-class approach

Markup authored with DuVay classes is static HTML and needs no component registration at all. Import duvay.js only when a test exercises the behavior layer (dropdowns, dialogs, toasts, theme cycling).

Keyboard and accessibility checks

Because the rendered output is native elements, accessibility assertions are direct: query for role and aria-* attributes, dispatch keyboard events, and check document.activeElement. No wrappers or test ids are required.
