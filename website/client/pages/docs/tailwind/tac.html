Using with Tailwind

DuVay and Tailwind coexist cleanly. Use DuVay components for structure and Tailwind utilities for one-off tweaks — DuVay for rigidity, Tailwind for fluidity.

No class collisions

DuVay namespaces everything under the w- prefix and <w-*> custom elements, so its classes never clash with Tailwind utilities. Its reset only touches base elements that Tailwind's Preflight already handles compatibly, and its aggressive content resets are scoped to .w-body, .w-app, and .w-reset wrappers.

Control the override direction

DuVay component classes and Tailwind utilities share the same specificity, so without help the winner depends on load order. Import DuVay into a lower cascade layer so Tailwind utilities always win.

Tailwind v4:

@layer duvay, theme, base, components, utilities;
  @import "https://d31ma.github.io/DUVAY/latest/duvay.css" layer(duvay);
  @import "tailwindcss";

Tailwind v3:

@layer duvay;
  @import "https://d31ma.github.io/DUVAY/latest/duvay.css" layer(duvay);
  @tailwind base;
  @tailwind components;
  @tailwind utilities;

Result

Now a DuVay button takes DuVay's styling and Tailwind's radius, regardless of source order:

<button class="w-btn w-btn-filled rounded-full">Save</button>

DuVay's few !important rules ([hidden], reduced-motion) still hold, since !important inverts layer precedence.
