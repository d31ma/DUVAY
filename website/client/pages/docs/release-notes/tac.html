Release notes

DuVay releases follow CalVer (YY.WW.DD). The full history lives in the repository CHANGELOG and on GitHub Releases. Breaking changes are always called out under a Breaking heading; see the upgrade guide for migration steps.

26.35.01

Released 2026-08-24

Cross-platform

  • Every component in the Core contract is now implemented on all five platforms — 46/46 on web, Apple, Android, Windows and Linux. The 21 Tier 2 components landed in batches across all four native platforms together, so none raced ahead. See Platform parity.
  • Each native component wraps the primitive that platform already provides rather than redrawing it: AdwStatusPage for the GNOME empty state, NavigationSplitView on Apple for its adaptive sidebar, Material's ModalBottomSheet for its scrim and dismissal actions, and NumberBox composed on Windows because the WinUI type is sealed.
  • A new Platform parity page, generated from spec/, showing which components each platform implements and — separately — whether that platform may be advertised as supported.
  • Every platform gained a snapshot suite. A publishable status now additionally requires a signed verification record, so a port cannot be advertised as supported without one.

Accessibility

  • A new Accessibility page describing what DuVay guarantees and how each guarantee is enforced.
  • bun run test:a11y runs axe over every registered element against WCAG 2.0/2.1/2.2 A and AA, once per platform skin. All six runs produce identical results, which is the token architecture holding rather than a coincidence.
  • Fifteen accessibility defects fixed. The most consequential: .w-sr-only was only defined inside the time picker, so w-heatmap and w-video rendered screen-reader-only text visibly. It is now a documented global utility.
  • w-pie, w-pie-segment, w-hotkey and w-hover-card now forward aria-label to the element carrying the ARIA role, so they can be given an accessible name at all.
  • w-file-upload's dropzone is a group rather than a button when it contains a browse button, since a button may not contain focusable children; its file input is now named.
  • w-calendar moved aria-selected from the day button to the gridcell, where it is valid.
  • Date-picker day cells and range-slider thumbs now meet the WCAG 2.5.8 24×24 minimum; w-virtual-scroll is keyboard-reachable.

Tokens

  • New --w-on-scrim: the foreground for content over --w-scrim. Video controls previously used --w-on-primary, which inverts with the palette and rendered at 1.37:1 in dark mode.
  • The five platform skins are now generated from tokens/platform/**, so skin values are part of the token pipeline rather than hand-authored CSS.
  • A component level completes the primitive → semantic → component ontology.
  • Windows gains Tokens.xaml, a ResourceDictionary of themed brushes, so XAML markup can reach the palette through {StaticResource}.

Fixed

  • inset on a switch could shrink the track on Material and Fluent, whose tracks already enclose the thumb. It now only ever grows.
  • The iOS and macOS skins used the background shorthand on toolbars, which silently wiped .w-toolbar--image.
  • The iOS and Material skins rounded the top corners of fullscreen bottom sheets.

26.34.07

Released 2026-08-23

Highlights

  • Five platform skins selected with w-os on <html> — ios, android/material, macos, windows/fluent, linux/adwaita — each as its own entrypoint (duvay-<os>.css) or layered from platforms/. Auto-detected from the user agent; an explicit attribute always wins. See Platform skins.
  • w-density rescales control geometry orthogonally to theme and skin; compact stays above the WCAG 2.5.8 AA touch-target minimum.
  • The design tokens are now DTCG JSON under tokens/, generating tokens.css and themes.css, with automated contrast and skin-rule gates.
  • Every component gains property setters (value, disabled, checked, …), so frameworks that bind by property work without adapters.
  • Native Tier 1 libraries — SwiftUI, Jetpack Compose, WinUI 3, GTK4/libadwaita — pass a shared 116-vector conformance suite; the parity matrix only advertises human-verified support.

26.34.03

Released 2026-08-19

Highlights

  • Restores the non-zero corner radius scale, so components render with rounded corners again instead of square ones.
  • w-btn forwards authored ARIA state — aria-pressed, aria-expanded, aria-controls, aria-haspopup, aria-current, aria-labelledby, aria-describedby — to the rendered control, which is the element assistive technology exposes. aria-pressed is withheld from the link form, where it is not valid.
  • The progress components forward aria-label, aria-labelledby, and aria-describedby onto the element carrying role="progressbar", so the indicator is no longer unnamed.
  • Adds a Using with Tailwind guide covering namespace safety and the cascade layer import that keeps Tailwind utilities winning.

26.31.06

Released 2026-08-01

Highlights

  • Completes component-name coverage against the pinned Vuetify 4.1.7 inventory, including avatar groups, command palettes, range and month pickers, heatmaps, highlights, mask inputs, pie charts, unified progress, and video controls.
  • Adds a generated API inventory and fallback docs pages for every registered DuVay web component and every declared attribute.
  • Adds browser behavior tests for the new components and corrects the source scanner so parity and API documentation only count attributes implemented by the component being inspected.
  • Improves command-palette semantics, preserves keyboard focus while video controls update, keeps new visualizations contained on narrow screens, and hardens inline color inputs.

26.31.02

Released 2026-07-27

Breaking

  • DuVay is no longer published to any package registry. There is no npm install path — use the hosted GitHub Pages URLs, or vendor the files. Bare imports such as @import "@d31ma/duvay-css/core.css" move to @import "https://d31ma.github.io/DUVAY/latest/core.css".

26.31.01

Released 2026-07-27

Breaking

  • The npm package is now @d31ma/duvay-css. Update installs and package imports from duvay-css; hosted GitHub Pages URLs are unchanged. (Superseded by 26.31.02.)

Highlights

  • Expanded Light DOM component behavior and API references across application, navigation, overlay, form, data-display, date and time, upload, and motion components.
  • Migrated the docs to the Tachyon website/client/ layout and expanded component, feature, style, directive, accessibility, installation, and upgrade coverage.
  • Added common web-component sizing, hover elevation, and scoped-theme attributes.
  • Raised compact text to a 12px default floor and standardized coarse-pointer controls on a 44px minimum touch target.
  • Hardened rendered text and attributes plus high-risk button, FAB, upload, icon-adapter, and inline-style inputs.
  • Made documentation builds reproducible with a pinned, checksum-verified Tachyon binary.
  • Made registry publication, tagging, GitHub releases, and immutable Pages assets operate on one verified source commit.

26.27.04

Released 2026-07-02

Breaking

  • Replaced every DuVay-owned data-w-* attribute with the consistent w-* prefix across CSS, web components, motion helpers, documentation, examples, tests, and generated distribution assets. Applications using CSS-class components must rename hooks such as data-w-theme to w-theme and data-w-dialog-open to w-dialog-open.

Changed

  • Added uniform, responsive API references across component documentation.
  • Gave Bottom sheets, Icon buttons, Sheets, and Toolbars dedicated documentation routes instead of forwarding their sidebar entries to unrelated page anchors.

Added

  • Added regression coverage that prevents legacy attribute prefixes, missing component API references, and broken sidebar destinations from returning.
